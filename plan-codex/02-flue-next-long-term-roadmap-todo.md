# flue-next 长期展望与 TODO

更新时间：2026-06-22  
用途：记录用户已提到但尚未精确定义、或明确属于后续阶段的事项。这里的内容不应抢占 MVP，除非用户后续把某项提升为当前开发范围。

## 1. 长期产品方向

`flue-next` 长期应从“一个手表桌面”演进成三层平台：

1. 稳定 Launcher 核心：应用列表、表盘、通知、负一屏、控制中心、设置、设备适配。
2. 表盘生态：WatchMaker `.watch` 导入、表盘商店、预览、编辑器、社区资源。
3. 高级商业能力：激活码、试用、私有商店、会员特效、管理后台。

长期原则：

- 主流程优先稳定、省电、低延迟。
- 高级视觉效果必须可关闭、可降级、可按设备能力分档。
- 外部参考项目只参考公开行为和 API，除非获得授权，不复制源码和素材。
- 所有未来功能都要通过模块边界扩展，不把业务继续塞回 Launcher 主 Activity 或大 ViewModel。

## 3. 功能 TODO 池

### 3.1 视觉特效

- kyant 液态玻璃库接入。
  - 先研究性能。
  - 砍掉高成本特效。
  - 分 Basic/Standard/Enhanced/Experimental 档开放。
  - 低性能设备默认关闭。
- Telegram 个人主页头像上滑水滴模糊效果。
  - 调研能否用于上下应用图标模糊。
  - API 31+ 可尝试 RenderEffect + 自定义 shader。
  - API 30 以下考虑 GL 或静态 snapshot。
  - 首版只做实验，不承诺上线。
- 头部和底部卷积核大小随 y 轴改变的 blur。
  - 做成 `ScrollLinkedKernelBlur`。
  - 应用列表、设置、负一屏共用。
  - 低版本降级为半透明渐变。
- 圆屏蒙版黑边控制。
  - 默认圆形。
  - 拉杆调整圆角/圆形裁切。
  - 适配表盘下沉、控制中心下拉、通知中心拉出。

## 6. 长期工程债预防清单

每新增一个大功能前检查：

- 是否新增了可测试的领域模型。
- 是否新增了 schema 和迁移。
- 是否有性能分档。
- 是否有低版本降级。
- 是否所有用户可见文案都来自 `strings.xml`。
- 是否能在圆屏/方屏/背屏预览。
- 是否不依赖单个全局 ViewModel。
- 是否没有把业务逻辑写进 Composable。
- 是否没有复制旧版大文件。
- 是否有 benchmark 或至少手动真机性能记录。
