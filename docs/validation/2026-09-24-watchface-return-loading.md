# 表盘市场标签与返回加载提示验证

## 修改

- 市场列表卡片将“受保护”标签放到名称右侧，名称最多两行并省略溢出文字。
- 加载门控在同一表盘已就绪后保留状态，不因刷新令牌改变而盖住渲染器保留的画面；冷启动、切换到另一表盘仍等待就绪。
- 就绪回调按表盘状态和刷新令牌隔离，旧回调不能撤销当前表盘的就绪状态，也不能提前放行新的加载。
- `.watch` 渲染器重新绑定同一份已就绪内容时，立即向宿主同步就绪状态，不必等待已去重的绘制通知或 6 秒超时。
- 普通目录扫描当前不会增加刷新令牌；保留编辑器通过共享令牌通知内容变更的行为。

## 回归证据

- 原门控提取后的测试出现 3 个预期失败：同表盘刷新重新等待、接受错误令牌、旧表盘回调覆盖当前就绪状态。
- 原渲染器的重绑定测试失败：真实源完成绘制后，新绑定的回调没有收到就绪通知；测试同时检查源对象保留。
- 修复后全量 `:app:testDebugUnitTest`：246 个套件，1896 项测试，1895 项通过、1 项跳过，0 失败、0 错误。
- 门控测试使用独立 Compose Recomposer 验证状态转换；渲染器重绑定测试使用 Robolectric。这些测试不等于设备上的应用往返验证。

## 设备验证边界

当前 `adb devices -l` 没有连接设备。用户确认问题发生在导入的 `.watch` 表盘；本次修复覆盖已确认的门控和通知缺陷，尚不能证明用户设备上每次闪现都由同一触发条件造成。

真机需复测：连续打开外部应用并返回、短暂熄屏再返回、编辑保存后返回、切换到另一张表盘，以及进程冷启动。普通返回应直接恢复表盘，编辑结果应更新，冷启动和真实切换仍应等待完整画面。
