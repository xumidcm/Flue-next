# 圆屏界面、应用列表布局与小组件恢复设计

## 目标

本轮在不改变方屏既有行为的前提下，统一圆屏页面的初始定位、弦宽缩放、控件形状与安全区；同时将应用列表布局从 UI 风格中解耦，并为真正失效的小组件绑定增加可恢复路径。

## 设置页初始位置

- 圆屏页面继续保留顶部和底部半屏滚动留白。
- 默认首次进入页面时，将第一个可操作选项置于屏幕垂直中心。
- 页面标题和可选的分组标题位于该选项上方，但仍属于同一个滚动列表，因此用户可以下拉把标题移动到屏幕中心。
- 已保存过滚动位置的页面优先恢复原位置，不强制重新定位。
- 搜索跳转仍将目标项放到屏幕中心。
- 方屏的初始位置和滚动恢复逻辑保持不变。

实现上由纯函数决定圆屏首次进入使用的初始 item index，页面显式声明第一个可操作项的 index，避免把 SectionTitle 误当成选项。

## 圆屏控件形状与内容留白

引入明确的圆屏控件角色，停止仅依赖宽高比阈值决定是否回退：

- `Capsule`：普通按钮、开关行、选择行、动作行、滑块外层、表盘选择卡和市场中的行状操作控件。圆屏强制使用胶囊轮廓。
- `Panel`：多行表单、大型编辑器控制组、对话框内容、纵向信息卡。继续使用各 UI 风格的普通圆角。
- `Preview`：表盘预览画布与需要检查真实比例的媒体区域。保持原始尺寸和形状，不参与弦宽缩放。

胶囊控件的水平内容 padding 在现有值上增加约 6dp，使文字、图标和尾部控件向内收；Panel 和方屏不增加该 padding。

现有 `RowCapsuleShape` 可以保留给未声明角色的兼容调用点，新修改的核心控件必须显式选择角色，避免滑块或表盘选择因高度变化再次退回圆角矩形。

## 表盘市场圆屏适配

- 顶栏、搜索、筛选控件、列表卡片与网格卡片使用圆屏安全区。
- 可滚动卡片按自身中心位置应用弦宽等比缩放，测量仍使用纯布局坐标，绘制只使用 graphics layer。
- 列表和网格均保留顶部、底部可滚动留白，使边缘卡片可以移动到屏幕中心。
- 卡片封面随整张市场卡片缩放；不会单独裁切或改变资源比例。
- 方屏维持原有网格列数、间距和尺寸。

## 表盘编辑器圆屏适配

- 表盘预览画布保持全尺寸、不应用弦宽缩放。
- 预览下方的 Tab、工具栏、属性控制组和操作按钮使用圆屏安全区。
- 可滚动控制项应用与设置页相同的弦宽坐标算法。
- 滑块外层与行状选择控件使用 Capsule；复杂多行编辑面板使用 Panel。
- 横向工具条允许横向滚动，避免在圆屏弦宽较窄处压缩文字或重叠。

## 全局 UI 大小提示

“全局 UI 大小”滑块下方增加次要说明文字：

> 调整后如遇显示异常请重新启动。

文字使用主题次要文本色和较小字号，作为滑块内容的一部分参与圆屏缩放。

## 默认 UI 风格

- 没有保存过 `ui_style` 的新安装默认使用 `MIUIX`。
- 非法或无法解析的保存值回退到 `MIUIX`。
- “重置设置”将 UI 风格恢复为 `MIUIX` 并写入 DataStore。
- 已有合法保存值不被迁移或覆盖。

## 应用列表布局与风格解耦

`LayoutMode` 扩展为三个持久化值：

- `List` -> 原生纵向列表
- `Honeycomb` -> 原生蜂窝
- `Grid` -> 原生密集网格

`AppListBackendPolicy` 只根据 `LayoutMode` 选择渲染器，不再读取 `UiStyle`。切换 Apple Watch、Material 3 或 MIUIX 只改变颜色、形状和动效语言，不改变应用列表布局。

外观设置页增加三项互斥选择。新安装与重置设置继续默认 `Honeycomb`；已有 `List` 和 `Honeycomb` 保存值保持兼容。

## 小组件绑定校验与恢复

Android 系统服务会持久化正常分配和绑定的 appWidgetId，因此设备重启本身不应触发无条件重分配。现有 application-owned `AppWidgetHost` 与 Activity `onStart`/`onStop` 监听生命周期修复保留。

渲染前增加绑定有效性检查：

1. DataStore 中的 ID 必须为有效正值。
2. ID 必须出现在当前 host 的 `getAppWidgetIds()` 中。
3. `AppWidgetManager.getAppWidgetInfo(id)` 必须存在，且 provider 与保存的 widget key 一致。

有效时直接创建 host view，不做任何迁移。

失效时由单次恢复协调器处理，避免 Compose 重组重复分配：

1. 查找原 provider；provider 不存在时显示不可用占位，不循环重试。
2. 分配新 ID，并调用 `bindAppWidgetIdIfAllowed()`。
3. 静默绑定成功且 provider 无配置页时，持久化新 ID，删除旧系统记录并刷新卡片。
4. provider 需要配置，或系统不允许静默绑定时，不冒充恢复原配置；显示明确的“重新绑定”操作，复用现有系统绑定/配置流程。
5. 新 ID 绑定或配置失败时立即删除，DataStore 保留旧记录供用户重试，避免泄漏 host ID。

该恢复同时覆盖系统备份还原、系统服务记录被清理、provider 被卸载重装等真实失配场景，而不会破坏正常重启后仍有效的配置型小组件。

## 测试与验收

按测试驱动方式实现：

- 设置初始位置纯函数：圆屏首次进入居中首个可操作项；保存位置和方屏不改。
- 控件角色 Shape 策略：Capsule 强制半高圆角，Panel 使用风格圆角。
- 应用列表策略：三种 LayoutMode 在三种 UiStyle 下始终映射到同一对应渲染器。
- 默认设置策略：新安装、非法值和重置均为 MIUIX，合法已有值保留。
- 小组件绑定恢复策略：有效 ID 不分配；失效 ID 单次恢复；失败清理新 ID；需要配置时不自动覆盖。
- 运行相关单元测试、`testDebugUnitTest` 和 `assembleDebug`。
- 不使用 ADB；圆屏视觉效果与真实小组件重启恢复需最终实机验收。
